# AI 审阅流程图

[RELEASING.md「先过 AI 审阅」](../RELEASING.md#先过-ai-审阅)的图解：一个改动从开 PR 到发布，要经过哪几道检查。规则以 RELEASING.md 和 `scripts/ai_review_gate.py` 为准，改了流程记得同步改这里。

## 从开 PR 到发布

```mermaid
flowchart TD
    A["写代码的会话<br/>推到分支、开 PR"] --> CI["CI / macos（push）<br/>测试、打 dmg、MCP 端到端"]
    A --> G1["AI 审阅（pull_request）<br/>跑门禁：还没审过 → 红"]
    A --> R["没写这段代码的会话或子代理<br/>跑 /code-review、自己测、在界面上看"]
    R --> P["用仓库所有者的账号发评审<br/>## AI 审阅（最新提交号）+ 结论"]
    P --> G2["AI 审阅（pull_request_review）<br/>跑门禁"]
    G2 --> RR["重跑同一提交的<br/>AI 审阅（pull_request）"]
    RR --> SAME["两条检查结果一致"]
    SAME -->|"结论：没有必须修的问题，可以合。"| OK["都是绿的"]
    SAME -->|"有必须修的问题，先别合。"| FIX["改代码，推新提交"]
    FIX -->|"新提交上只有 pull_request 那条，红的"| R
    OK --> M["合并进 main"]
    M --> T["打标签 v*"]
    T --> REL["release.yml<br/>先查标签指向的提交（见下面第三张图）<br/>再测试、签名、公证、发布"]
```

- 检查都在 PR 页面上：`CI / macos` 每次推送都跑；「AI 审阅」按触发它的事件列成两条，发审阅那次会顺手重跑开 PR 那次，两条跑完后是一样的颜色。重跑还没跑完、或者没重跑成功时会暂时不一样，看 pull_request_review 那次的日志。推了新提交，新提交上先只有 pull_request 那一条（红的），发了审阅才出现另一条。
- 合并按钮本身不等审阅（main 没有设分支保护）。真正拦住没审过的代码的是发布那一步：标签指向的提交没通过门禁，就不打包、不发布。
- 审完又推了提交，就要再审一次，标题写新的提交号，可以注明「增量」。

## 门禁怎么判断（`ai_review_gate.py pr <编号>`）

```mermaid
flowchart TD
    S["取 PR 最新的提交 head"] --> F{"有没有算数的评审？<br/>仓库所有者发的、没撤回、<br/>第一行以「## AI 审阅」开头"}
    F -->|"没有"| N1["没通过：还没有 AI 审阅"]
    F -->|"有"| H{"从新到旧找：<br/>第一行写着 head 的提交号<br/>（7 位以上）"}
    H -->|"找不到"| N2["没通过：最新的提交还没审过"]
    H -->|"找到最近的一条"| C{"它的「结论：」那一行<br/>是不是「没有必须修的问题，可以合。」<br/>或「可以合」（后面最多一段「无挡合并项」这类括号备注）"}
    C -->|"是"| Y["通过"]
    C -->|"不是"| N3["没通过：结论不是可以合"]
```

- 认两种结论：「没有必须修的问题，可以合。」（「的问题」可以省），和另一个审阅 agent 写的「可以合」加一段括号备注；「可以合并」也算。短的「可以合」后面不能再有别的字，括号备注只认「无挡合并项」「无必须修」「无 Must-fix」「无阻塞项」这几种（前面可以带「Comment；」，详见 RELEASING.md）。只看结论这一行，条件要写进结论行。「修完就可以合」「可以合，但……」「可以合（先修 X）」这类带条件的写法都算不通过。
- 几条评审都写着最新的提交号时只看最新的一条：后来的审阅说「先别合」，前面的「可以合」就不算了。
- 格式不对的评审（比如第一行是「## 审查结论」）不算数，但发出去照样会触发一次检查：最新提交还没有通过的审阅就是红的，已经有了就照样是绿的。

## 打标签发布时（`release.yml` 的第一步）

```mermaid
flowchart TD
    T["推了标签"] --> D{"标签名里有连字符？<br/>如 v1.3.0-test.1"}
    D -->|"没有：正式版"| MAIN{"标签指向的提交在 main 上？"}
    MAIN -->|"不在"| X1["不发布"]
    MAIN -->|"在"| PR1{"是从哪个 PR 合并进来的？"}
    PR1 -->|"找不到"| X1
    PR1 -->|"找到"| GATE["对那个 PR 跑门禁"]
    D -->|"有：测试版"| PR2{"从 PR 合并进 main 的，<br/>或者是某个还开着的 PR 的最新提交？"}
    PR2 -->|"都不是"| X1
    PR2 -->|"是"| GATE
    GATE -->|"通过"| BUILD["测试、签名、公证、发布"]
    GATE -->|"没通过"| X1
```
