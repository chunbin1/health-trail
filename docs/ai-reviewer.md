# 给审阅模型的说明

这份是写给审 health-trail PR 的那个模型看的。写代码的是另一个会话：它推 PR，再按你的审阅改问题。你只负责审，不改代码，也不推提交。

门禁（`scripts/ai_review_gate.py`）只认一种格式，格式不对的审阅等于没审，PR 上的「AI 审阅」检查会一直是红的。完整规则在 [RELEASING.md「先过 AI 审阅」](../RELEASING.md#先过-ai-审阅)，流程图在 [ai-review-flow.md](ai-review-flow.md)；这里只写每次审阅要照着做的部分。

## 每次审阅

1. 查 PR 最新提交的前 7 位，标题要写它：

   ```bash
   gh pr view <编号> --json headRefOid --jq '.headRefOid[0:7]'
   ```

2. 审代码：跑 `/code-review`，自己跑 `make test`，对照 [CLAUDE.md](../CLAUDE.md) 的「硬规则」；改了界面的，按 CLAUDE.md「验证」在浏览器里看一遍。
3. 把审阅写进一个文件（比如 `review.md`），发之前用下面的「发之前自查」检查一遍。
4. 用仓库所有者的账号发评论（GitHub 不让自己批准自己的 PR，所以用 `--comment`）：

   ```bash
   gh pr review <编号> --comment --body-file review.md
   ```

5. 写代码的会话按审阅改完、推了新提交，就对**新提交**再审一次，标题写新的提交号，可以注明「增量」。旧提交上的审阅不算新提交的。

## 格式

```
## AI 审阅（bb8969f）

**结论：没有必须修的问题，可以合。**

**验证**
- 跑了什么、结果如何

**必须修** / **建议修** / **小问题**
1. ……
```

- **第一行**：`## AI 审阅（<最新提交的前 7 位>）`，正文的第一个字就是 `#`，前面不能有空行。后面可以加说明，比如 `## AI 审阅（bb8969f，增量）`。
- **结论行**：正文里第一个以「结论」开头的行（前面的 `#`、`*` 这些符号不算）。结论要和「结论：」写在**同一行**。
- **不要用「结论」做小标题**：`## 结论` 本身就会被当成结论行，它后面没有「可以合」，于是判不通过，下面一行再写 `**可以合**` 也没用。
- 通过时，结论行写成这两种之一：
  - `**结论：没有必须修的问题，可以合。**`（「的问题」可以省）
  - `**结论：可以合**`，后面最多跟一段括号备注，备注只能是「无挡合并项」「无必须修」「无 Must-fix」「无阻塞项」，前面可以带「Comment；」或「Approve；」，比如 `**结论：可以合**（Comment；无挡合并项）`
- 有要先修的：`**结论：有必须修的问题，先别合。**`
- 结论行里不能带条件。「修完就可以合」「可以合，但要先修……」「可以合（待 CI 通过）」都判不通过；条件写在下一行，门禁也看不到。

## 发之前自查

在仓库根目录跑，把 `review.md` 换成你的文件、`15` 换成 PR 编号：

```bash
python3 -I -c "import sys; sys.path.insert(0, 'scripts'); from ai_review_gate import passes, names; b = open(sys.argv[1]).read(); print('第一行：' + ('对' if b.startswith('## AI 审阅') and names(b.splitlines()[0], sys.argv[2]) else '不对')); print('结论行：' + ('能过' if passes(b) else '过不了'))" review.md "$(gh pr view 15 --json headRefOid --jq .headRefOid)"
```

两行都是「对」「能过」再发。结论本来就是「先别合」时，第二行是「过不了」才对。

发完以后可以再确认一次门禁的判断：

```bash
python3 -I scripts/ai_review_gate.py pr 15
```

## 出过的错

| 写法 | 结果 |
| --- | --- |
| 第一行是 `## 结论`（PR #15 的第一次审阅） | 第一行不是 `## AI 审阅`，整条不算，门禁说「还没有 AI 审阅」 |
| `## 结论` 做小标题，下一行写 `**可以合**` | `## 结论` 被当成结论行，判不通过 |
| 审的是旧提交，又推了新提交 | 门禁说「最新的提交还没审过」 |
| `**结论：可以合**（待 CI 通过）` | 括号备注不在允许的几种里，判不通过 |
